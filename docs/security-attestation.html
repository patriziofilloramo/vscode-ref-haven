The evidence

Every claim below maps to a real artifact in the repository or the package. Nothing to take on trust.

✓

Zero network primitives, enforced by the build

A guard test scans every source file and fails if a network call, a code-execution primitive, telemetry, or an unaudited process/browser handoff appears. Process execution lives in a single file; browser opening in a single file.

$ npm run test:unit — data-egress guard
✓ imports no network or code-loading module
✓ contains no network or code-execution primitive
✓ confines process execution and browser handoff to their audited files
✓ ships zero production dependencies
✓

Git cannot reach the network

Every Git process starts with transports disabled: any fetch/push attempt would be refused by the protocol itself. Proxy, SSH, external diff, and inherited repository-redirection environment variables are cleared; no shell.

git -c protocol.allow=never …
env: GIT_ALLOW_PROTOCOL="" · GIT_TERMINAL_PROMPT=0 · GIT_PROXY_COMMAND cleared
✓

Zero runtime dependencies

No third-party code runs in the extension host. The VSIX contains only compiled JavaScript, package metadata, the icon, and declared documentation — no source, no node_modules, no other payload.

// package.json
"dependencies": {}
// package verified · 0 .ts · 0 node_modules
✓

No telemetry, no account, no automatic discovery

No telemetry API, no usage events, no account system, no remote configuration service. The extension activates without network events and logs stay in the local panel, with sensitive metadata redacted.

// manifest contributions
"activationEvents": ["onStartupFinished"] · untrustedWorkspaces: supported: false
